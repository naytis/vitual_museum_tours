# Java-компонент виртуальной музейной экскурсии

Рабочий консольный редактор на Java 21. Он хранит музеи, экскурсии и редакции в JSON, импортирует подготовленные Python панорамы, управляет карточками, информационными метками и направленными переходами между залами. Куратор может вернуть редакцию с замечанием или согласовать её. После согласования редактор фиксирует опубликованный выпуск и экспортирует комплект для будущего просмотрщика.

## Открытие в IntelliJ IDEA

1. Распакуйте архив в папку tour-editor внутри вашего общего репозитория.
2. В IntelliJ IDEA выберите File → Open и откройте pom.xml как проект Maven.
3. Выберите JDK 21 для проекта. Дождитесь загрузки зависимости Gson.
4. Откройте src/main/java/ru/museum/Main.java и нажмите зелёный треугольник рядом с main.
5. Рабочая папка запуска должна быть tour-editor. По умолчанию база сохраняется в data/catalog.json, изображения – в data/assets.
6. Для хранения в другой папке передайте её путь как единственный аргумент программы. Путь с пробелами заключите в кавычки в поле Program arguments.

В PyCharm откройте Python-часть общего репозитория. Компоненты обмениваются JPEG и manifest.json. Подготовку изображения запускает специалист перед импортом.

## Запуск без Maven

В архив включены Gson 2.13.2, её лицензия и готовый tour-editor.jar. Для готового JAR требуется Java 21 или новее.

Пример PowerShell с JDK, установленным в отдельной папке:

```powershell
$jdk = Read-Host "Полный путь к папке JDK 21"
& "$jdk\bin\java.exe" -jar .\tour-editor.jar
```

Сборка из исходников с запуском:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Jdk $jdk
```

Компиляция и 25 проверок:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Jdk $jdk -Test
```

Тестовый класс ComponentTest имеет метод main. Его также можно запустить из IntelliJ IDEA, указав аргумент demo-python/manifest.json и рабочую папку проекта. Протокол проверок сохранён в evidence/test-log.txt. Пример каталога после сценария двух публикаций находится в evidence/sample-catalog.json. Тест создаёт временную базу и удаляет её после проверки. Maven test сам по себе не запускает этот исполняемый тестовый класс.

## Первый маршрут из двух залов

Программа запрашивает каждое значение на отдельной строке. Идентификатор – полная строка UUID, которую программа печатает при создании объекта. Каталог доступен командой 1. Внутри меню пути вводятся без окружающих кавычек.

1. Команда 2 – создайте музей.
2. Команда 3 – укажите ID музея и название экскурсии. Первая редакция выбирается автоматически.
3. Команда 5 – создайте два зала. Сохраните их ID.
4. Команда 6 – назначьте первый зал начальным.
5. Команда 7 – укажите ID первого зала, путь demo-python/manifest.json и имя gallery.png.jpg из поля output.
6. Повторите команду 7 для второго зала, выбрав hall.jpg.jpg.
7. Команда 8 – создайте экспонат в первом зале. Введите название, автора, датировку, описание.
8. Команда 10 – добавьте метку для этой карточки в том же зале. Для демонстрации задайте yaw = 0, pitch = 0.
9. Команда 11 – добавьте переход из первого зала во второй, yaw = 90, pitch = 0. Для обратного пути создайте отдельный переход.
10. Команда 13 – проверьте маршрут. Каждый зал должен иметь панораму и быть достижимым из начального, каждая карточка – хотя бы одну метку.
11. Команда 14 – передайте редакцию куратору.
12. Команда 15 – укажите имя куратора, «нет» и замечание. Редакция вернётся в черновик. Команда 9 позволяет исправить карточку.
13. Повторите команды 14 и 15. Для согласования введите «да».
14. Команда 16 – зафиксируйте опубликованную редакцию.
15. Команда 18 – задайте новый каталог, например release-1. Он получит tour.json и assets с JPEG.
16. Команда 17 – создайте новую редакцию. Измените карточку командой 9, повторите проверку и согласование, затем опубликуйте. Предыдущая редакция получит состояние ARCHIVED.
17. Команда 19 показывает все поля выбранной редакции в JSON. Для переключения между редакциями используйте команду 4.

Публикация в этом компоненте означает фиксацию согласованного выпуска в локальном каталоге. Экспорт создаёт данные для последующего размещения и просмотрщика. Сферический веб-просмотр, размещение на хостинге и учётные записи сотрудников относятся к дальнейшей разработке. Имя куратора вводится вручную.

## Связь с Python

Выполните обработку изображений существующей Python-программой. В Java-компоненте укажите путь к полученному manifest.json и имя нужного файла из поля output. Имя может быть gallery.jpg или gallery.png.jpg: Java читает фактическое значение манифеста.

Для импорта нужны schemaVersion = 1, valid = true, status = ok и положительные width/height. Ресурс должен существовать внутри каталога партии. Java копирует его в своё хранилище, вычисляя SHA-256 для имени копии. Одинаковые байты хранятся под одним именем. После импорта исходная партия не нужна для открытия сохранённого тура.

Проверку формата, пропорций и декодирование пикселей выполняет Python. Java использует подготовленные результаты. Связь с залом задаётся при импорте.

## Структура и ответственность

- Model – музей, экскурсия, редакция, зал, панорама, экспонат, метка и переход.
- Repository – интерфейс хранения каталога.
- JsonRepository – реализация хранения через Gson, запись через временный файл и атомарную замену.
- ManifestImporter – импорт подготовленных ресурсов.
- TourService – операции редактирования, проверка маршрута, согласование, выпуск и экспорт.
- Main – консольные команды и блокировка каталога от одновременного открытия.
- ComponentTest – проверка сценариев и отказов.

Новая редакция копирует содержимое предыдущего выпуска и получает собственный ID. Идентификаторы залов, карточек и меток сохраняются внутри копии, поэтому обращение к объекту определяется парой «редакция + ID». На каждую экскурсию допускается одна рабочая редакция. До успешного сохранения копии каталога изменения не применяются к состоянию сервиса. Незавершённый импорт может оставить неиспользуемый ресурс в assets, но опубликованные данные при этом сохраняются.

## Общий репозиторий

Сохраните Python-компонент на прежнем месте, а эту папку добавьте как tour-editor. В терминале корня общего репозитория:

```powershell
git add tour-editor
git commit -m "Добавить Java-компонент редактирования музейной экскурсии"
git push
```

Файлы build, target, data и настройки IDE исключены из Git. Готовый JAR можно хранить как демонстрационную сборку. Исходники находятся в src.
